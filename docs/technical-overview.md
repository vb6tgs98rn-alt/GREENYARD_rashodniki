# Green Yard — техническая документация

Документ для партнёров и технических специалистов. Описывает архитектуру,
компоненты, модель данных, внешние интеграции, безопасность и соответствие
требованиям законодательства РФ.

Версия приложения: 1.2.0 · Дата: август 2026 · Правообладатель: Гусейнов Давид.

---

## 1. Назначение

Green Yard — веб-приложение для управления посуточной арендой квартир:

- учёт бронирований и финансов (юнит-экономика по каждому объекту);
- автоматическое общение с гостями через мессенджеры (бот);
- электронные договоры аренды;
- приём оплаты проживания от гостей;
- управление горничными и уборками.

Приложение рассчитано на нескольких арендодателей (multi-tenant): каждый работает
только со своими данными, изоляция обеспечивается на уровне базы данных.

## 2. Архитектура

Классическая схема «тонкий клиент + управляемый бэкенд» без собственных серверов.

```
┌─────────────────────┐        HTTPS         ┌──────────────────────────────┐
│  Браузер (SPA)      │  ◀───realtime───▶    │  Supabase                    │
│  статичные ESM-     │                      │  ├─ PostgreSQL (RLS)         │
│  модули на          │  ──REST / RPC──▶     │  ├─ Auth (JWT)               │
│  GitHub Pages       │                      │  ├─ Realtime (подписки)      │
└─────────────────────┘                      │  └─ Edge Functions (Deno)    │
                                             └──────────────┬───────────────┘
                                                            │ исходящие/входящие
                                       ┌────────────────────┼────────────────────┐
                                       ▼                    ▼                    ▼
                               RealtyCalendar          Точка Банк            Okidoki
                               (брони, webhook)    (оплата, OAuth 2.0)   (эл. договоры)
                                       │
                                       ▼
                        Telegram / MAX / WhatsApp (боты для гостей и горничных)
```

Ключевые принципы:

- Сборка фронтенда не требуется — модули ES грузятся браузером напрямую, SDK
  подключается с ESM-CDN.
- Вся бизнес-логика с секретами вынесена в серверные Edge Functions.
- Секреты (ключи банка, договоров, токен бота) никогда не попадают в браузер.
- Источник истины по броням — внешний сервис RealtyCalendar; в базе хранится зеркало.

## 5. Серверная логика (Edge Functions)

Все функции опубликованы по адресу `https://<project>.supabase.co/functions/v1/<имя>`.

| Функция | Назначение | Авторизация |
|---|---|---|
| `telegram-bot` | Бот для гостей и горничных в Telegram/MAX/WhatsApp: приветствие, инструкции по заезду, договор, ссылка на оплату, чат с менеджером | Секретный токен вебхука; служебные маршруты — по JWT менеджера |
| `tochka-api` | Интеграция с Точка Банком: подключение по OAuth 2.0, создание ссылок на оплату, сверка статусов, приём вебхука | JWT приложения; вебхук — подпись RS256 |
| `okidoki-proxy` | Единая точка вызова Okidoki API: создание и отправка договоров; API-ключ клиента подставляется на сервере | JWT приложения |
| `okidoki-callback` | Приём вебхуков Okidoki о смене статуса договора, уведомление менеджера | Внешний вебхук |
| `realtycalendar-webhook` | Приём бронирований из RealtyCalendar, определение владельца по `agency_id`, запись в `rc_bookings` | Определение владельца по `agency_id` |
| `consent-api` | Приём и отзыв согласий на обработку персональных данных (152-ФЗ) | JWT приложения |
| `unit-economics` | Серверный расчёт юнит-экономики по объектам | JWT приложения |

### Маршруты `tochka-api`

```
GET  /status      статус подключения арендодателя
POST /connect     начать подключение, вернуть ссылку подтверждения
GET  /callback    возврат из Точки после подтверждения разрешений
POST /disconnect  отключить Точку
POST /pay         создать/получить ссылку на оплату по брони
GET  /payments    платежи по брони
POST /refresh     обновить справочники (счёт, ТСП) и вебхук
POST /poll        сверить статусы неоплаченных ссылок
ANY  /webhook     вебхук Точки (тело — JWT, подпись RS256)
```

## 7. Внешние интеграции

- RealtyCalendar — источник бронирований. Один вебхук-URL обслуживает всех
  клиентов; владелец определяется по уникальному `agency_id`, который клиент вводит
  в приложении. Схема «один URL — много пользователей».
- Точка Банк — приём оплаты проживания. Подключение по OAuth 2.0, ссылки на оплату
  (эквайринг/СБП), кассовый чек по 54-ФЗ. Вебхук платежей подписан RS256.
- Okidoki (doki.online) — электронные договоры аренды. Ключ клиента хранится в базе
  и подставляется на сервере; на клиент не передаётся.
- Мессенджеры — бот работает одновременно в Telegram, MAX и WhatsApp: выдаёт гостю
  инструкции, договор и ссылку на оплату, пересылает переписку менеджеру.

## 8. Безопасность

- Изоляция данных на уровне БД: RLS на всех таблицах, пользователь видит только свои
  строки (`auth.uid() = user_id`). Запись во внешне-наполняемые таблицы выполняют
  только Edge Functions от имени `service_role`.
- Секреты только на сервере: ключи Точки, Okidoki и токен бота хранятся в переменных
  окружения функций и в таблицах без публичных RLS-политик. В браузер не попадают.
- Вебхук Telegram защищён секретным токеном: сторонние запросы отклоняются (HTTP 401).
- Вебхук Точки проверяется по подписи RS256.
- Служебные таблицы (`cron_config`, `tochka_connections`) имеют явный запрет доступа
  для ролей `anon`/`authenticated` — только через служебный ключ.
- HTTPS на всех соединениях; аутентификация по JWT (Supabase Auth).

## 9. Соответствие законодательству РФ

- 152-ФЗ «О персональных данных» — модуль согласий (`consent-api`, таблицы
  `privacy_policies`, `user_consents`): фиксация согласия, отзыв, версии политики.
- 54-ФЗ «О применении ККТ» — кассовый чек формируется при оплате через Точка Банк
  (карта/СБП с чеком); email гостя запрашивается для отправки чека.
- НК РФ (режимы НПД/УСН) — учёт доходов ведётся с оглядкой на налоговый режим
  арендодателя.

## 10. Развёртывание и эксплуатация

- Фронтенд: статические файлы публикуются на GitHub Pages. Сборка не нужна.
  Служебные папки (`supabase/`, `sql/`) исключаются из публикации через `_config.yml`,
  чтобы исходники бэкенда и схема БД не раздавались как статика.
- Бэкенд: Edge Functions деплоятся в Supabase; SQL-миграции применяются в проекте
  Supabase. Пошаговая инструкция подключения RealtyCalendar — в `DEPLOY.md`.
- Плановые задачи: напоминания горничным по расписанию (конфигурация в `cron_config`,
  запуск защищён секретом).
- Переменные окружения функций (значения не разглашаются): идентификатор/секрет
  приложения Точки, redirect URI, токен бота, секрет вебхука Telegram, служебный ключ
  Supabase, секрет плановых задач.

## 11. Ограничения и особенности

- Источник истины по броням — RealtyCalendar; приложение хранит зеркало и
  пересчитывает финансы по вебхукам.
- Кассовый чек по 54-ФЗ формируется только для оплат «карта/СБП с чеком»; для чистого
  динамического QR СБП чек не формируется.
- Один вебхук Точки соответствует одному приложению (client_id); платёж связывается
  по идентификатору операции.
- Приложение проприетарное; копирование, распространение и обратная разработка
  запрещены без письменного разрешения правообладателя (см. `LICENSE`).
